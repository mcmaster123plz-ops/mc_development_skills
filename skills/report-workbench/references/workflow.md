# 从资料到报告的通用流程

## 把业务判断和文件制作分开

报告先回答业务问题，再组织证据和文字，最后装入文档。参考文件可同时提供多个作用，但必须区分：合同规定工作边界，已确认数据提供事实，往期稿提供表达示例，模板提供版式。一个作用不能替代另一个作用。

常见返工发生在参考用途未分清、资料与对象映射不稳、证据不足以支持文字，以及模板改变后仍沿用旧替换位置。分别检查这些关系，不把文件生成等同交付完成。

## 一 建立任务卡

需求尚未确定时读取 [planning.md](planning.md)，以初步设计和资料需求开始。资料核对与框架设计同步推进，不等待所有字段或全部数据到齐才开始思考结构。

只记录已知要求和会改变输出的缺口：

| 要素 | 要确认的实际问题 |
|---|---|
| 读者与用途 | 给谁看，要求对方理解什么或据此做什么 |
| 报告类型 | 监测、校验、调查、技术方案、专题分析或工作总结 |
| 范围 | 哪个时间段、区域、对象；是单份还是按期分别生成 |
| 输出 | Word/PDF/段落；输出位置；是否有正式版式 |
| 依据 | 哪些材料有业务约束，哪些只是参考；哪些数据已确认 |
| 缺口 | 缺数字、缺判断、缺图片、缺证据还是仅缺排版 |

用户说“先定框架”时交付可讨论的框架与资料清单，不提前把未经确认的内容排成大批文件。用户已同意完整制作时持续推进，不把例行小选择反复交给用户。

## 二 以章节问题组织资料

每章至少对应一个要回答的问题。例如“校验情况”回答疑点是什么、依据是什么、结论是什么；“技术方案”回答方法为什么可行、如何执行、如何验收。

| 报告方向 | 主要证据 | 适合的章节内容，按任务取舍 |
|---|---|---|
| 监测与校验 | 当期数据、可定位影像、判读或测量记录 | 摘要、概述、数据与方法、结果/案例、成果应用、总结 |
| 调查与专题分析 | 事件记录、多时相资料、调查笔录、统计 | 背景与问题、调查范围、事实、分析、结论及建议 |
| 技术方案与论证 | 需求、指标、约束、备选方法和试验结果 | 目标、基础条件、方法比较、技术路线、实施与验收 |
| 阶段或年度总结 | 已完成工作、成果、进度、问题与后续计划 | 工作概况、主要工作、成果、问题、下一阶段安排 |

以上是选章依据，不是强制目录。摘要、概述和总结在长篇正式报告中通常各有作用：摘要压缩主要内容；概述解释任务；总结回答达到什么、剩余什么。三处不要重复堆叠同一段话。短报告或用户指定结构可以合并。

## 三 组织可复用的内容单元

按需建立四类信息：

- **共性事实：**项目名、范围、日期、数据来源、指标口径、单位等。
- **工作单元：**点位、事件、样品、监测断面、子项目或专题；内部稳定编号，报告编号另设。
- **素材：**图、表、照片、视频片段、数据文件；一项一条登记并连接工作单元。
- **章节依赖：**正文哪些章节依赖哪些单元、数据和图件。

同一个事实只维护一个当前值及其出处。摘要、统计和总结读取相同台账。用户改结论时保留原值、决定与来源记录；未解决冲突不静默消失。

不要把“待补”都做成用户填写任务。AI可以整理日期、计算数量、提取原始文本和发现矛盾；需要用户补充的是无法从现有资料确定的业务事实、目标位置或决定。

## 四 先检查素材能否支撑内容

看三层：

1. 文件可用：能读取、清晰度足够、没有损坏。
2. 映射成立：时间、对象、位置和编号对得上。
3. 证据适用：图片实际显示了文中目标和关键特征，能支撑该层级的判断。

EXIF坐标相符不能跳过第三层；图片好看也不能替代第三层。已有最终结果而缺过程时，可以整理真实存量记录并标出不确定处，不把假设的工作经过写成事实。

## 五 写一份样稿并固定版式契约

把模板记录为可检查的契约：源文件、哈希、页面与节、字体样式、标题层级、图表、页码、目录范围、可编辑位置及应保留部分。任何模板版本变化都先检查契约。

使用已存在的内容控件、书签、稳定标题或明确的替换位置。段落索引只在指纹和结构已验证的同一模板内有效。不要把本次67个段落、3个表格等数量放进通用引擎。

图文组件按需要复用：单图、双图对照、统计表、时序图、流程图、案例段落。图件按比例适配，不能拉伸；表格总宽度同时检查页面可用宽度、单元格边距与图片尺寸。目录与页码必须由最后一次排版验证。

## 六 批量或增量处理

| 变化 | 直接修改 | 必须联动复核 |
|---|---|---|
| 新周期 | 当期事实、案例、图件 | 时间、数量、摘要、总结、编号与页码 |
| 换图但目标不变 | 图件与日期 | 图中文字是否仍准确、目标是否可辨、图题和分页 |
| 换成新目标 | 单元、坐标/对象、素材及结论依据 | 逐项段落、分布图、统计、编号及相关章节 |
| 增删单元 | 单元台账与明细 | 数量、类别汇总、分布图标签、图题、摘要总结和目录 |
| 改数字或口径 | 当前事实与计算 | 所有引用段落、表、图、单位和结论 |
| 改模板或框架 | 模板契约与替换映射 | 样式、节、图表、引用和全部页码 |

缓存已经确认的参考解析、匹配关系、压缩图和模板检查结果；源文件变化时只失效相关缓存。保留内容审查和排版审查两个状态。图片变化不能因文档版式稳定就略过语义审查。

## 七 检查与交付

内容检查关注事实、来源、论证、限制。关联检查关注单元、图片、日期、数字、图题及版本。排版检查关注字体、表格、分页、目录和页码；实际渲染后逐页确认。

“脚本通过”“文件生成”“版式已检查”“用户验收”是不同状态。报告仍有关键证据缺口时可交付修订稿并说明缺口，不把自动检查结果写成业务成果已经证实。

每轮保留一份简短交接记录：当前要求、采用的数据/模板版本、已完成部分、待核对项及下一步。用户换模型或会话后从这里继续，不重新复盘全部历史。
